- **Embedding-based dedup** [6.1 #3] (roadmap item). Two differently-worded reports of the same incident (say, the police and the fire brigade on the same fire, 500 m apart) now become one event when an embeddings provider is set.
  - `server/src/embeddings.ts`: `Embedder` interface; `HttpEmbedder` for any OpenAI-style `/embeddings` endpoint (Mistral, OpenAI, Voyage), with a 10 s timeout, ordering by index and validation of the answer; `NoEmbedder` (default); `FakeEmbedder`, deterministic (synonym groups hashed into 64 dimensions) for tests. Only public source text (the extracted title + summary) is sent, never user data or locations. Config: `EMBEDDINGS_URL`, `EMBEDDINGS_API_KEY`, `EMBEDDINGS_MODEL`, optional `EMBEDDINGS_DIMENSIONS` and `EMBEDDINGS_MIN_SIMILARITY` (default 0.8). The start-up line says which dedup is active.
  - Clustering: the hard rules stay first (NINA id root, CAP references, NWS never fuzzy-merges, so NWS alerts aren't embedded at all). Candidates still have to share the category, start within 6 hours and lie close together; among those, cosine similarity decides when both sides have a vector, word overlap otherwise. Reports within 300 m still merge as before. A new event keeps its first report's vector; an event created while the provider was down gets one from its next report. When the provider fails, the report is clustered by word overlap and nothing is stored.
  - Storage: `Store.saveEventEmbedding()` and `Store.eventSimilarities()`. Postgres migration 4 enables pgvector and adds `event_embeddings` (vector, model, `ON DELETE CASCADE`); similarity is pgvector's cosine distance, filtered by model and dimension so vectors from different models are never compared. No ANN index (the dimension depends on the provider, and candidates are a handful of active events). SQLite stores the vector as JSON and computes cosine in JS.
  - Interpretation: the Postgres migration lock is now database-wide instead of per schema, because `CREATE EXTENSION` is database-wide (otherwise parallel test schemas could race on it).
  - CI: the `postgis/postgis` service has no pgvector, so a step installs `postgresql-16-pgvector` into it (same as `server/docker/postgres/Dockerfile`). Not verifiable here; the first CI run on this push is the check.

## 2026-11-17

- **PostGIS matching** [6.4]: last part of the Postgres split; the original "Postgres + PostGIS + pgvector" item is now done except pgvector, which moved to "Embedding-based dedup".
  - New `Store.usersNear(area, bufferM, now)`: the users whose current location (updated in the last 24 hours) is within radius + buffer, or whose saved place overlaps the area, each with their saved places. `Pipeline.deliver` uses it instead of loading every user and their places one by one; `match` still makes the final call, so who gets an alert is unchanged.
  - Postgres (migration 2): enables PostGIS in `public`, adds generated `geography(Point)` columns to `users` and `saved_places` with GIST indexes, and a CHECK that a place radius is at most 5 km (the API limit, now the shared `MAX_PLACE_RADIUS_M`). The query is two index lookups joined by `UNION`. Because PostGIS measures on the spheroid and `match` on a sphere, the search is widened by 1 % + 10 m and `match` trims it, so both backends pick exactly the same users. SQLite applies the same rule in JS.
  - Measured on local Postgres with 50,000 users spread across Germany: the plan uses `users_geog`, and `usersNear` takes about 2 ms (an `OR` version took about 460 ms, which is why it's a `UNION`). Migration 2 also applied cleanly to a database created by migration 1 with existing data, and to an empty database without PostGIS installed.
  - Tests: new `server/test/matching.test.ts`, run per backend: location vs. saved places vs. neither; stale locations ignored but places kept; 60 users placed within ±100 m of the edge, where `usersNear` + `match` must equal `match` over all users. Server: 43 passed + 2 skipped without Postgres, 63/63 on Postgres. Both typechecks clean; demo runs.
  - For Flori: Postgres now requires the PostGIS extension. The managed Postgres on the hosting line under "Needs a human" must offer it (Fly, Supabase, Neon, RDS and Cloud SQL all do). If the app's database role can't create extensions, run `CREATE EXTENSION postgis;` once as an admin.
